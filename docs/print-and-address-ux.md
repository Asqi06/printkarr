## Progressive pricing and cash checkout

Base rates remain editable in `/admin/pricing`. Default B&W is ₹2 and colour ₹4. Progressive slabs count B&W + colour sides, copies and all documents together: 1–50 at ₹2/₹4, 51–150 at ₹1.80/₹3.75, 151–300 at ₹1.60/₹3.50, 301+ at ₹1.40/₹3. Each slab applies only to its portion; mixed documents share the basket discount proportionally. Lower admin festival rates never increase to the floor. Existing payment reservations keep their quoted prices.

Print processing applies once per checkout: 1–10 sides ₹2, 11–30 ₹4, 31–75 ₹6, 76–150 ₹8, 151+ ₹10. Stationery-only baskets have no print-processing fee. Cash adds ₹10 per checkout; wallet and online payments retain only page processing and delivery. Checkout and receipts show each fee and applicable savings separately. Website orders are required; WhatsApp print requests are not processed.

Cash requires explicit customer consent and cannot replace an open gateway payment. It reserves/consumes stock and pack quota once, starts fulfilment with `paymentStatus=cod_pending`, and leaves the wallet untouched. The legacy purchase status `PAID` represents confirmed fulfilment; it does not mean cash has been received. Assigned riders or admins must record the exact amount while the package is out for delivery before completion sets financial payment status to paid. Uncollected cancelled cash restores stock/quota without creating wallet credit. Wallet top-ups save the checkout destination and return there after verified payment; eligible offers show bonus expiry and non-withdrawable terms.

`lib/pricing-cod.test.js` checks slab boundaries, monotonic totals, frozen reservations, shared basket fees, consent/ownership, gateway/COD races, replay, cash collection and cancellation using fictional records. These tiers are the initial business policy; actual paper, ink and delivery costs are needed to assess profit.

## Checkout and automatic print recovery (8 October 2026)

The Render alias and www links now redirect browser GET/HEAD requests for checkout/auth/account pages to the public origin, not just SEO pages. Generated Google callback, referral, share and QR links also use the public origin on known hosts, even if a proxy host points at Render. Localhost development keeps its own origin. Agent API requests retain their origin and bearer authorization. The default referrer policy sends the origin to HTTPS payment providers; checkout and wallet routes already set origin-only referrers. This removes an alias checkout path but is not proof of Razorpay merchant-domain approval. Verify the approved website against the live key's merchant account if the exact gateway error persists. Payment failures keep the checkout and show the provider description with a retryable button.

Admin print actions use the current status and payment eligibility. Stale forms refresh instead of trying an illegal transition; unpaid jobs cannot be confirmed or claimed. The capped, explicitly approved owner-test method remains printable. Manual takeover is labelled accurately: changing status does not send paper. Failed unpaid standalone jobs can return to customer checkout only after the operator acknowledges that the next automatic attempt prints every page. Paid/shared purchases cannot use that recovery action.

The agent owns a claimed job until it reports completion or failure. A lost claim cannot fail another worker's job. Admin stop requests are polled between sets and during Windows monitoring; the monitor cancels only jobs it owns. Progress records the current phase and completed sets. A whole-order retry requires an explicit partial-output warning. Admins can download the supplied branded cover, B&W PDF and colour PDF separately to recover only missing pages.

Windows job monitoring now reads numeric status flags, handles completed retained jobs and rejects reports with no observed spool job. Both split sets must submit before output verification, and automatic callbacks cannot complete or fail a manually owned job. Queue drain still requires an operator's physical page check.
